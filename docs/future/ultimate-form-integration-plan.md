# NovelGo 终极形态整合重构规划

> 基于「吸收 → 创作 → 质检」单向价值链的终局架构分析与迁移路线。
> 本文是**规划文档**（诊断 + 蓝图 + 路线），不含实现代码。
> 前身文档：`volume-scoped-pipeline-implementation-wbs.md`（卷级流水线，阶段 0–4 已全部完成）。
> 立项语境：产品定位取舍讨论的结论——"该删的没有，该接的有两处；问题不在设计多了，在两条线之间少了一根管子"。本文把这根管子升级为终局架构。

---

## 0. 北极星

**一句话定位：流水线保证签约下限，心智提取抬高文风上限。**

产品终态是一台**单向价值链引擎**：

```
吸收（参考书 → 心智/套路/风格）→ 创作（蓝图 → 章节）→ 质检（体检 → 修复 → 冻结）
          ↑____________ 单向赋能：风格与事实经统一装配器注入每个环节 ____________↓
```

- **下限产品（质检段）**：闸门流水线回答「对不对、能不能签约」——硬约束，产品脊柱。
- **上限功能（吸收段）**：心智/套路/表达 DNA 回答「像不像、有没有辨识度」——软约束，产品护城河。
- **两段共用一个真理层**，经**一根管子（上下文装配器）**注入所有 agent 环节。

**判断准则**（对任何既有/新增功能生效）：*它喂给谁？* 答不上来的即冗余候选；答得上来的，按"无消费路径且无接线计划"才允许删除。

## 2. 结构性诊断——弱点与断线（代码证据）

| # | 症状 | 证据 | 定性 |
|---|------|------|------|
| W1 | **流水线不认文风**：重写/体检提示词零引用 persona/心智/风格 | `internal/pipeline` 对 persona/pattern/style 零匹配；`chapterRewritePrompt(novelID, item, ch, bibleText)` 只注入事实块 | **真断线，最大杠杆** |
| W2 | **风格素材悬空**：仅 CRUD + 管理页，无任何 prompt 消费点 | `app/style.go` 只有仓储 API；pattern/prompts 仅文字提及"六维画像思路"未吃数据 | **真悬空** |
| W3 | **双平面平行摆放**：聊天创作与流水线在 UI/叙事上互不相识 | 无共享上下文契约；入口平级堆砌 | 产品结构问题（"冗余感"的直接来源） |
| W4 | **风格资产非结构化**：心智/表达 DNA 是 markdown 技能文件，机器不可校验 | `kind: mental` 落盘为技能；无风格维度枚举/阈值/台账 | 结构性缺口（W1 无法自动体检的根因） |
| W5 | **产品取舍无数据**：功能去留靠讨论不靠使用证据 | 无本地使用度量 | 度量缺口 |
| W6 | **供应商稳定性**：LLM 流式挂起、子 Agent 长跑 | 已知环境问题；已有部分熔断（fixProviderIdleTrip=10） | 可靠性缺口 |

## 3. 终极形态：三层圣经 + 一台装配器 + 一条价值链

### 3.1 核心概念一：三层圣经（Unified Book Bible）

「本书的真理」从一层扩成三层，**同一套快照/审计/retcon 机制横向复用**（机制不动，只加维度）：

| 层 | 管什么 | 现状 | 终态 |
|----|--------|------|------|
| **事实层 Facts** | 对不对：人物/地点/时间线/伏笔 lifecycle | ✅ 台账+快照+审计已完备 | 保持，作为模板 |
| **风格层 Voice** | 像不像：表达 DNA/句式指纹/POV 与视角/时态/意象密度/对话-叙述比 + 心智三件套 | ⚠️ 有资产（心智技能、风格素材）但非结构化且断线 | **结构化 Voice 台账 + 风格快照** |
| **意图层 Intent** | 该不该：蓝图/pitch/平台约束/读者 POV/卖点 | ⚠️ 散落（book-pitch、story-blueprint、平台透镜） | **统一 Intent 面板**，进装配器 |

三层的共同纪律（平移 2.3 阶段验证过的容错契约）：**有则注入、无则降级为空串（与旧行为逐字一致）、按预算截断、坏数据宁缺勿错。**

### 3.2 核心概念二：上下文装配器（ContextAssembler）——"一根管子"的终态

现状是每类 agent 提示词各自拼上下文（chat: `BuildSystemMessages`；pipeline: 各 `*Prompt` + `bibleBlock`）。终态收敛为**唯一装配入口**：

```
ContextAssembler(novelID, purpose) →
  facts:  EstablishedFactsText          （已有，原样平移）
  voice:  persona + 表达 DNA + 心智摘要 （P0 新增）
  intent: 蓝图 + 平台约束 + 读者 POV    （P0 新增，v1 可先用现有文本源）
```

**注入契约与调用方解耦**，消费方全部走装配器（purpose 区分预算与取舍）：

- 聊天写作（`BuildSystemMessages` 重构为装配器的一个 purpose）
- S3 章节重写（`chapterRewritePrompt` 的 `bibleBlock(bibleText)` → `assembler.Block("facts","voice")`）
- S4 体检 / S5 修复 / 一致性巡检 / statesync / 提取（提取也可消费 facts 做证据前置，已有 EvidenceRetriever 先例）

### 3.3 核心概念三：价值链三工厂（IA 终态）

信息架构从「功能堆」收敛成三段旅程，入口按旅程排布而非按功能类型：

1. **吸收工厂**（参考书 → 资产）：导入参考书 → 提取（套路/心智/风格画像）→ 入库 Voice 层与技能库；空态引导：*未提取心智的书在重写时提示"可提取参考书心智以保持文风"*——把闲置功能变成漏斗。
2. **创作工厂**（意图 → 章节）：蓝图/pitch（Intent）→ 对话式写作/代笔（**自由区**，低摩擦）+ 流水线写作/重写（**质检区**，高保证）。**双速语义刻意保留**（见 §6.1），但产出汇流到同一正文 + 台账，且都从装配器取上下文。
3. **质检工厂**（章节 → 可交付）：S4 体检（8 维 + **新增文风漂移维度**）→ S5 修复/重写 → 卷末冻结（**事实 + 风格双快照**）→ 巡检张力报告。

## 4. 目标架构分层与模块契约

```
┌─ 界面层 ─────────────────────────────────────────┐
│  吸收工厂 │ 创作工厂（自由区+质检区） │ 质检工厂      │  ← 旅程式 IA，空态引导漏斗
└──────────────────────────────────────────────────┘
┌─ 执行层（双速共用）──────────────────────────────┐
│  chat agent │ Rewrite/Fix/Patrol agents │ statesync │  ← 全部经装配器取上下文
└──────────────────────────────────────────────────┘
┌─ 装配层（P0 新增，单总线）───────────────────────┐
│  ContextAssembler: facts │ voice │ intent 块契约   │  ← 有则注入/无则降级/预算截断
└──────────────────────────────────────────────────┘
┌─ 资产层（真理层）────────────────────────────────┐
│  Facts 台账+快照 │ Voice 台账+快照(P1/P2) │ Intent │  ← 快照/审计/retcon 机制横向复用
└──────────────────────────────────────────────────┘
┌─ 基础设施 ───────────────────────────────────────┐
│  skillrun 多轮 loop │ 评分门禁 │ 供应商熔断 │ 模型配置 │
└──────────────────────────────────────────────────┘
```

关键契约决定：

- **装配层是唯一注入入口**：任何 agent 提示词不得绕过装配器手拼上下文（既有 `bibleBlock` 调用点平移进装配器）。
- **资产层机制复用而非重建**：Voice/Intent 的冻结、审计、retcon 复用 facts 的快照与状态机实现（`snapshot` 包的 Freeze/Diff/Restore 按表扩展）。
- **执行层保持双速**：自由区不加闸门，质检区闸门不变；二者唯一共享的是装配器与写入工具（已是现状，保持）。
- **文风校验的分级纪律**：Voice 进巡检/体检初期一律 **warning 级 + 只报告不改写**（沿用 A5 纪律），阈值经使用数据再调。

## 5. 整合重构路线（P0–P4）

**迁移策略：接总线，不推倒。** 状态机/闸门/快照/retcon 脊柱零语义改动，只扩展注入点与维度。

### P0 · 接线（杠杆最大，闭环"冗余感"）

- ContextAssembler v1：`bibleBlock` 扩展为 facts/voice/intent 三块契约；v1 的 voice 直接取现有 persona/心智技能文本（不等结构化）。
- 接入点：S3 重写、S4 体检、S5 修复提示词注入 voice；`BuildSystemMessages` 改走装配器。
- **验收**：①重写章节文风漂移主观对比可辨识改善；②voice 缺省时输出与旧行为**逐字一致**（降级测试）；③既有测试全绿。

### P1 · 风格结构化（闭 W4）

- Voice 画像 schema：六维（句式指纹/高频词禁忌词/节奏/幽默与确定性语气）+ 小说维度（POV 与视角处理/时态/意象密度/对话-叙述比）。
- 风格素材（W2）二选一裁决：并入 Voice 成为素材源（推荐，闭悬空），或删除入口。
- 提取产物结构化落库（技能文件保留为人类可读视图，双写）。
- **验收**：Voice 台账可查询、可 diff、进快照。

### P2 · 质检扩展（文风进闸门，闭 W1 彻底）

- S4 体检新增文风漂移维度（warning 级起步，不阻断）；issue 沿用三枚举字段（forward_fix/retcon_candidate 标签）。
- 风格快照随卷冻结（G_freeze 双快照）；retcon 支持风格回改（复用 A3 状态机，零新流程）。
- **验收**：漂移 issue 自动进既有修复/重写路由；冻结卷风格可回滚。

### P3 · IA 整合（闭 W3）

- 三工厂旅程化 UI 重排；空态引导漏斗（未提取 → 重写提示）；设置页瘦身（写作评分配置并入质检工厂面板，数据目录等基础设施留设置）。
- 叙案统一：上限/下限一组词贯穿 onboarding 与入口文案。
- **验收**：任意功能入口能回答"喂给谁"；新用户按旅程走通吸收→创作→质检。

### P4 · 可靠性与度量（闭 W5/W6）

- 供应商重试矩阵/熔断完善（扩展现有 idle trip）；长跑子 Agent 任务可见性。
- 本地使用度量（功能使用率，纯本地不上传），为取舍规则供数据。
- （可选）V3 跨书聚合产物直接进 Voice 层。

每阶段独立可交付、独立可回退；**P0 单独即可闭环产品叙事与冗余感**，是推荐的第一刀。

## 6. 不做什么（反模式与非目标）

1. **不合并双速语义**：chat 的低摩擦自由创作与流水线的高保证闸门是刻意分工；给 chat 加闸门会毁掉创作流畅度，给流水线撤闸门会毁掉签约下限。共享的是上下文与写入工具，不是交互语义。
2. **不删提取/心智**：跨书心智聚合是护城河；因断线而删资产等于"管子没接就宣布水源无用"。
3. **不做大爆炸重写**：不重构状态机、不换存储、不动快照事务纪律（raw SQL restore 等教训不回退）。
4. **不引入云端账号/协作**（本规划范围外）：本地优先不变。
5. **Voice 层初期不上 error 级阻断**：文风是品味问题，warning + 只报告起步，避免误报骚扰作者。
6. **不为结构化而结构化**：P0 先用现有文本源接线，结构化收益经 P1 验证再投。

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| voice 注入拉长提示词、挤占预算 | 与 facts 同款预算截断；voice 块独立可关；purpose 区分预算 |
| 结构化 Voice 采集成本高 | 渐进：P0 注入现有文本 → P1 结构化；提取链路自动产出，不给作者加填表负担 |
| 文风漂移误报骚扰 | warning 级 + 只报告不改写（A5 纪律）；阈值经 P4 度量再调 |
| 重构破坏既有闸门 | 只扩注入点不动状态机；"无 voice 时逐字一致"降级测试锁定 |
| 双快照拖慢冻结 | 风格快照量小（画像非正文）；同事务提交，复用 uk_volume_snapshot 冲突重试 |
| IA 重排引发老用户迷失 | 旅程式为默认视图，功能型入口保留为次级导航，不做硬移除 |
