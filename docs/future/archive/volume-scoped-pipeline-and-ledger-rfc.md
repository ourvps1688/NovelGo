# RFC: 卷级作用域流水线 + 四维系列圣经（台账）设计

> 状态：草案（待评审）
> 关联：前次 S5 有界化改造（commit d393be38）、issue 原子化（signability-audit.md）、fix_type / FixStates
> 目标：从流程上根除"写第二卷时反复回头改第一卷"的怪圈，并把"台账"升级为覆盖角色 / 地点·弧线 / 时间线 / 读者视角四维的结构化系列圣经（series bible）。

---

## 0. 问题复述

当前 S0–S6 以"整本书"为唯一对象运行：S4 签约体检扫全书、S5 修复闭环无差别地"回头改"。流水线**没有"作用域"和"定稿"概念**——任何 issue 都不带"指向哪一卷、那一卷是否已定稿"的信息。于是只要体检说第一卷有问题，不管第一卷写完没有，S5 都会去改它。这正是"第一卷写完、写第二卷时又翻开第一卷重改"的必然结果，违背长篇"一卷一卷定稿"的写作逻辑。

---

## 1. 报告如何处理（分阶段落地路径）

> 本节的分阶段路径已细化为可执行工作分解（含数据字典、文件触点、验收标准），见 `volume-scoped-pipeline-implementation-wbs.md`。

本报告不一次性重写流水线，而是分四阶段、向后兼容地推进：

| 阶段 | 内容 | 风险 | 复用/新增 |
|------|------|------|-----------|
| 0. 评审 | 本 RFC 定稿（本次） | 无 | — |
| 1. 最小闭环 | issue 增加 `target_scope` 字段；S5 拒绝写冻结卷；S4 改为只扫当前卷 + 标注跨卷问题归属与维度 | 低 | 扩展既有 `fix_type`/`FixStates` |
| 2. 台账结构化 | 扁平台账 → 四维结构化 series bible；每卷冻结提交一份快照 | 中 | 新增 ledger schema + 快照 |
| 3. 审批与巡检 | retcon 审批闸门（作者显式拍板）+ 全书一致性巡检（建议性报告） | 中 | 新增闸门 + 巡检 agent |
| 4. 前端 | 卷管理 UI、冻结标识、retcon 弹窗、巡检报告视图 | 中 | 前端组件 |

**向后兼容**：既有单卷书当作"1 卷书"运行，行为完全不变；book-run 下挂 scoped sub-run，未分卷的项目直接走旧路径。

---

## 2. 核心架构：卷级作用域 + 冻结闸门 + 前向修复

1. **卷级流水线实例**：每一卷跑自己独立的 scoped sub-run（挂在 book-run 下），不再有"一次性审全书"的单体运行。每次审计的范围天然就是"当前在写的这一卷"。
2. **冻结闸门 G_freeze**：一卷通过 S4 体检 + S5 修复后进入**只读冻结态**；其正文不可再被自动修改，它对台账的贡献固化为一份**已提交台账快照（committed ledger snapshot）**。
3. **滚动式（增量）审计**：写第 N 卷时，S4 只扫第 N 卷正文，但校验依据是**第 1…N-1 卷提交后的台账快照**。前面的卷是"既定事实"，第 N 卷必须来适配它——而不是反过来。
4. **Issue 按"目标作用域 + 修复方向"分流**（关键判断）：
   - 目标 = 当前活跃卷 → 走正常 S5 修复（在当前卷内部改，前向，没问题）。
   - 目标 = 已冻结卷 → **绝不自动回写**。默认走"前向适配"：调整第 N 卷迁就前面的设定。仅当**硬矛盾且无法前向消解**（例如前面写死某角色已死，第 N 卷剧情需要他活着）时，才升为 **retcon 审批闸门**——由作者显式拍板是否破例回改前面卷；批准后才对冻结卷做一次受控、留痕的编辑。
5. **台账版本化**：每次冻结提交一份快照，当前卷在最新快照上扩展。这份不断增长的快照就是项目的"系列圣经"，前面卷的权威性由它保证，审计也就没有动机去重写前面卷——因为它们已经和自己的快照自洽了。

## 3. 台账（系列圣经）四维完整规格

**前向修复能否成立，完全取决于台账是否完整。** 后面卷要"有章可循"，四维缺一不可；任一一维缺失，前向修复就会退化成瞎改或被迫回头。四维均须**结构化存储（字段而非自由文本）**，以便 S4 能机器校验、S5 能精确路由。

### 3.1 角色（Characters）

冻结内容：
- **身份事实**：姓名、别名、性别、出生年/年龄、外貌锚点（如"左手刀疤""左撇子"）。
- **状态事实**：生死、当前所在地、所属阵营/势力、职业/身份。
- **能力上限**：力量天花板、已知技能、禁用/封印状态（防止后期偷偷加挂。
- **关系网**：与其他角色的关键关系（师徒 / 仇敌 / 恋人 / 血亲）。
- **语音特征**：口癖、视角惯用语（供一致性检查，非硬约束）。

一致性规则：已死角色不得复活（除非 retcon）；外貌/关系锚点不可静默改。

前向修复示例：第 N 卷写"他右手有疤"，但圣经记左手 → 改第 N 卷。
retcon 示例：隐藏身份揭晓、假死真活——作者主动决策，留痕。

### 3.2 地点 / 弧线（Locations / Arcs）

**地点**：
- 地理与归属：地名、控制势力、关键属性（如"断桥已于卷 2 毁"）。
- 地图状态快照：哪些地点可达 / 毁灭 / 封锁。

**弧线（两类）**：
- **角色弧**：主要角色的成长轨迹与当前阶段（起点 / 转折 / 目标）。
- **情节弧**：悬念线程状态（open / closed / 悬置）、未解谜题、伏笔清单及其预期回收卷。
- **主题弧**：贯穿全书的母题。

冻结与前向修复：地点/弧线在卷末状态固化；第 N+1 卷须在其上扩展。若第 N+1 卷把"已毁断桥"写成完好 → 改第 N+1 卷。**open 线程须被携带或显式关闭，禁止静默丢弃**（这是最易漏的跨卷 bug）。

### 3.3 时间线（Timeline）

- **绝对锚点**：关键纪元/日期、角色年龄、季节、卷间 elapsed 时长。
- **相对序列**：事件先后。
- **间隙标记**：卷间"空白期"须显式标注（避免后期推算漂移）。

冻结与前向修复：时间锚点固化；第 N+1 卷的"三年后"若与圣经"五年"冲突 → 改第 N+1 卷。**时间线是最高发的跨卷 bug 源**，圣经须同时存绝对锚点 + 间隙标记，禁止让模型"自行推算"。

### 3.4 读者视角（Reader Perspective / POV）

最易被忽视、却最关键的一维：

- **POV 名册**：哪些角色拥有 POV 章、限知 / 全知约束。
- **知识边界**：每个 POV 角色在各时间点"已知 / 未知"的事实。
- **读者已知态**：读者已被展示 vs 仍被隐瞒的信息（戏剧反讽、伏笔兑现）。

冻结与前向修复：
- **"读者当前相信 X"是事实**，后续卷须尊重——不能无 retcon 地"撤销"已揭示真相（否则读者感知断裂）。
- 限知 POV 不得写出其不可能知道的信息；第 N+1 卷若让限知角色泄露未知情报 → 改第 N+1 卷。
- 读者视角圣经防止**意外剧透**与**"不可能知识"**（角色说出他没渠道知道的事）。

---

## 4. 跨卷 Issue 路由矩阵（四维 × 修复方向）

每条跨卷 issue 必须标注 `target_scope` + 维度 + 方向。默认**前向适配**；仅硬矛盾且无法前向消解才升 **retcon**。

| 维度 | 典型跨卷问题 | 默认方向 | 升 retcon 的条件 |
|------|--------------|----------|------------------|
| 角色 | 第 N 卷外貌/关系与圣经冲突 | 前向（改 N） | 需让已死角色复活 / 推翻核心身份 |
| 地点/弧线 | 第 N 卷引用已毁地点为完好 / 丢弃 open 线程 | 前向（改 N） | 需改写前卷地理结局以服务新剧情 |
| 时间线 | 第 N 卷时长/年龄与锚点冲突 | 前向（改 N） | 需推翻已确立的大时间框架 |
| 读者视角 | 限知角色泄露未知 / 撤销已揭示真相 | 前向（改 N） | 需"吃书"重设读者已知态 |

---

## 5. 边角与护栏

- **累计漂移**：永远只允许前向适配，久了设定会失真 → 一道**全书"一致性巡检"作为建议性报告**兜底：它只告诉你"第 5 卷和圣经有 N 处张力"，**不自动改写**，改不改由作者定。
- **作者主动 retcon**：审批闸门是逃生舱，但它是"显式 + 留痕"的，不是循环自动触发。
- **晚期才发现的跨卷正文 bug**：归类为 retcon 候选，而非静默回写前面卷。
- **台账自身可错**：增设"台账审计"步骤，冻结前校验圣经自洽（防止垃圾进、垃圾出）。

---

## 6. 与现有代码 / 近期改动的衔接

- 复用 S0–S6、闸门、`Orchestrator.Advance`、issue 原子化（前次已做：signability-audit.md 要求 issue 原子化、标明归属）。
- **扩展 `fix_type` / `FixStates`**：给 issue 增加 `target_scope`（活跃卷 / 冻结卷 / 无）与 `dimension`（角色/地点弧线/时间线/读者视角）；S5 路由据其判断是否指向冻结卷。
- **审计 prompt 改造**：S4 只扫当前卷，并显式标注"跨卷问题"及其指向的作用域 + 维度（与原子化要求天然衔接）。
- **台账从扁平 → 四维结构化 + 版本快照**：复用现有"台账级"概念，但把自由文本升级为带四维字段的 series bible，每卷冻结提交快照。

---

## 7. 预期收益与开放问题

**收益**
- 根除"后卷改前卷"怪圈（写保护 + 前向默认 + retcon 显式）。
- S5 体量变小、自洽，前次"无限重试"炸裂感缓解。
- 系列圣经成可复用资产，利于续作 / 改编。

**开放问题（待阶段 2/3 细化）**
- 快照合并冲突：两卷并行写（少见）时快照如何序列化。
- retcon 的"受控编辑"如何实现留痕与可回滚（建议基于快照 diff）。
- 一致性巡检的触发频率与成本（建议按卷末 + 手动触发，而非实时）。
