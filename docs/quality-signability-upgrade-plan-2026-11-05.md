# 签约级质量升级计划（2026-11-05）

> 背景：目标是产出「签约级」网文。已在七猫发布两篇，编辑反馈「综合质量一般」。
> 本文回答：这套代码（NovelGO）该往哪里改，才能系统性地把综合质量顶到过签线。
> 结论先行：**现有系统是「正确性机器」，缺的是「商业可读性度量」与「真实反馈闭环」。
> 检测/修复闭环已经很强，不必推倒；要补的是情绪账、爽点密度机器验收、平台口径
> 强对齐、编辑反馈回流四件事。**

---

## 一、七猫审核口径（外部事实，代码要对齐的目标）

七猫是免费流量平台（广告分成，算法推荐，下沉市场），编辑与算法的口径高度一致：

| 维度 | 七猫实际要求 |
|---|---|
| 章长 | 首章 1000–1500 字（免费平台短章快节奏） |
| 开篇铺垫 | 前 200 字内入戏；前 500 字内出爆点/冲突；前 800 字内金手指亮相 |
| 黄金三章 | 第一章抓眼球（第一句就出事）、第二章立人设、第三章给甜头 |
| 节奏 | 「先抑后扬」：委屈→隐忍→爆发→打脸，每个情绪阶段不超过 300 字 |
| 爽点 | 密集、情绪递进清晰；考核指标是**完读率/留存率** |
| 文笔 | 要求相对宽松，重情绪调动与流量潜力，忌 AI 味同质化 |
| 投稿形态 | 开篇两万字 + 大纲（编辑初审→委员会复审→总编终审） |

「综合质量一般」翻译成七猫语言，大概率是：**开篇爆点不够快、爽点密度不够高、
情绪递进不够利、人设记忆点不够强**——注意没有一条是「一致性」。

## 二、现状盘点（代码能力全景，2026-11-05 勘察）

### 强项：正确性/一致性机器（行业少见的完整度）
- 检测四 kind + 工单闭环 + 人工确认→修复→显式复验（`internal/pipeline/`，零自动派发）。
- 签约体检八维评分（`internal/skill/builtin/signability-audit.md`）：开篇过签力/题材
  契合/人设卖点/节奏爽点/设定自洽/长线牵引/平台合规/读者视角，verdict+致命伤清单。
- 台账体系（角色/地点/弧线/读者认知）+ 结构检查器（伏笔生命周期/不变量/战力序）。
- 评分门禁（`internal/review/score.go` 6 维 0-100，低于阈值自动重写重试）+ 写后 CI
  （L0 十项确定性 + L1 五检查项）。
- 生成侧约束文案齐全：任务卡四件套（钩子/爽点/人设时刻/推进，缺一拒收，
  `internal/timeline/taskcard.go`）、写作方法论技能（opening-chapters/pacing-control/
  scene-beats/plot-hook/dialogue-subtext/deai-flavor）。

### 缺口（按对过签的影响排序）
1. **爽点密度/情绪曲线没有机器验收**。`internal/quality/checker_config.go:22-25`
   的 `BeatDensityMin` 注明「节奏曲线数据源尚未落地，本参数先行入配置」——爽点
   密度检查至今未实现；情绪曲线只有写后自查的文案要求（identity.go），无落库指标。
   「节奏拖沓/爽点不够」恰恰是免费平台编辑最常见的退稿理由，系统现在**测不出来**。
2. **读者维度只有「信息账」没有「情绪账」**。`internal/reader` 管读者知道什么
   （known/suspense/misconception），不管读者爽不闷——无逐章情绪值/张力曲线，
   无无聊点/弃读点建模。
3. **零真实反馈闭环**。全库无编辑反馈结构化入库、无七猫后台完读/追读数据对账；
   八维评分与 6 维判官的松紧度全部来自 LLM 常识模拟，从未被真实过签/退稿结果校准。
   「综合质量一般」这句反馈本身，系统没有能力消化。
4. **双轨评分无映射**：评分门禁 6 维（0-100）与体检 8 维（1-5）各说各话；评分只有
   最近一次快照，无趋势视图，「修复是否真的提分」无法回答。
5. **平台口径是静态文案**：`frontend/src/components/preference/platformTemplates.ts`
   把七猫标准写死在模板文案里供参考，但没有机制化为可执行的 CheckerConfig /
   生成约束 / 验收规则（章长、前 500 字爆点、300 字情绪段等都查不了）。
6. **低分维无自动改进路由**：体检发现低分维后，重写提示词（chapterRewritePrompt）
   是通用文案，不会定向加载 opening-chapters/pacing-control 等对应方法论技能。

## 三、优化路线图

### P0：把「综合质量」变成机器可度量、可修复（先做，收益最大）

**P0-1 平台风格 Profile 机制化（对齐七猫口径）**
- `internal/quality/checker_config.go` 增加平台 profile（章长目标、前 N 字爆点、
  爽点密度下限、情绪段长度上限），七猫 preset：章长 1000-1500、前 500 字爆点、
  黄金三章硬查。
- L0 新增确定性检查：`opening_hook`（前 200/500 字的冲突词/悬念词/异常事件密度）、
  `chapter_length_fit`（章长 vs 平台区间）、`beat_density`（爽点标记密度，
  数据源依赖 P0-2）。
- 前端 preference 平台模板从「文案参考」升格为「写入 CheckerConfig 的一键配置」。

**P0-2 情绪账/节奏账落库（P0-1 的数据源，也是 dim4 的度量基础）**
- 新表 `chapter_tension`（章→段落/beat 粒度的情绪值、张力值、爽点类型）：
  L0 用确定性近似（对话比、冲突词密度、句长方差、感叹/反问密度）先落一条基线曲线；
  L1 chapter-ci 回执增加 `tension_curve` 字段（LLM 标注段落级情绪起伏与爽点位置）。
- 基于曲线的检查：拖沓段检测（连续 ≥N 段张力平坦）、爽点断档（章内无情绪峰）、
  开篇坡度（前 500 字张力是否上扬）。
- 消费侧落地 `BeatDensityMin`（配置终于有数据喂），体检 dim4 的证据从主观星级
  变成曲线截图式证据。

**P0-3 双轨评分打通 + 趋势视图**
- 6 维判官 ↔ 8 维体检映射表（plot_advance/emotion_hook → dim4/dim1 等），
  判官分与体检分同源展示。
- `chapter_quality` 已有历史行，补前端趋势视图（逐章分数/发现数曲线、修复前后对比），
  回答「这次重写到底提分了没有」。

### P1：反馈闭环（把编辑和读者的话变成系统输入）

**P1-1 编辑反馈结构化回流（最快能吃到的现实信号）**
- 新增「反馈回流」工具/面板：粘贴编辑原话 → LLM 按八维分类拆解成维度问题 →
  落成两类产物：① 体检 issue（可走既有修复闭环）② 生成约束修订（写入
  upsert_preference / CheckerConfig，例如编辑说「节奏拖」→ 调高爽点密度下限）。
- 两次已发布作品的编辑反馈（哪怕只有「综合质量一般」+ 题材）是第一批输入。
- 复用既有架构：approval 的 feedback 注入、GateDecision feedback 落库都已存在，
  本项只是把「非结构化文本 → 结构化规则」补上。

**P1-2 真实数据对账（校准判官松紧度）**
- 「平台数据」面板：人工粘贴七猫后台逐章完读率/追读率 → 按章与 tension 曲线、
  八维评分对照 → 输出「流失点章节 × 低分维」交叉诊断。
- 这是唯一能让 LLM 判官从「模拟网文常识」进化到「贴合七猫口味」的信号源；
  不需要 API，人工粘贴即可起步。

### P2：生成侧强化（在度量和反馈就位后做，避免盲调）

**P2-1 低分维 → 生成技能定向路由**
- 体检低分维自动加载对应方法论技能进重写提示词（dim1→opening-chapters、
  dim4→pacing-control/scene-beats、dim3→character-design），替代通用 chapterRewritePrompt。

**P2-2 平台化写作模板**
- 七猫偏好的「先抑后扬打脸节奏」（300 字/情绪段）、短章快节奏等做成 scene-beats
  的可选节奏模板，生成时按平台 profile 选用。

**P2-3 对标书库（dim2 题材契合的数据源）**
- 赛道标杆书的结构特征样本库（钩子类型/爽点类型/节奏形态），题材契合评分有据可依，
  不再纯靠模型记忆「对标 XX 书」。

## 四、验收标准

| 项 | 验收 |
|---|---|
| P0-1 | 七猫 profile 下：前 500 字爆点/章长/爽点密度三项 L0 可检，不达标出 finding |
| P0-2 | 每章落库 tension 曲线；拖沓段/爽点断档可被检测并落工单 |
| P0-3 | 任一章可看 6 维↔8 维同源分与历史趋势 |
| P1-1 | 一段编辑原话 → 自动产出维度 issue + 约束修订，可走既有修复闭环 |
| P1-2 | 粘贴完读数据后能输出「流失章 × 低分维」对照诊断 |
| 终验 | 以七猫口径重跑两篇旧作体检，「综合质量一般」对应的维度应全部出 finding |

## 五、假设与待确认

1. 假设「综合质量一般」主要指向开篇/节奏/爽点/人设（免费平台编辑的高频退稿项）；
   **如有编辑原话，哪怕是只言片语，请提供**——P1-1 会把它变成第一批结构化输入。
2. 假设两篇已发布作品是网文长篇（非短篇）；题材（男频/女频、具体赛道）会影响
   平台 profile 的章长/爽点类型默认值，请补充。
3. 七猫后台数据可人工获取（创作者后台逐章数据）；若拿不到，P1-2 降级为纯编辑反馈校准。

## 六、实施顺序建议

P0-2（情绪账数据源）→ P0-1（平台口径机器验收）→ P0-3（评分打通）→ P1-1（反馈回流）
→ P1-2（数据对账）→ P2 按需。P0 三项互相咬合（P0-1 依赖 P0-2 的数据），预计是
一个独立的开发计划文档量级；P1-1 可以并行先行（不依赖 P0）。
