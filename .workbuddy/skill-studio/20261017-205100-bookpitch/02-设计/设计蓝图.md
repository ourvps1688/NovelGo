## B. 前端 v2 集成设计

### B.1 数据模型
- 保留 8 个独立 state（`title/description/tags/direction/genre/platform/style/oneLiner`）。
- 新增 `manualFieldsRef: React.MutableRefObject<Set<Field>>`，记录用户**手动编辑过**的字段（受自动覆盖保护）。
- 新增 `formRef` 保存最新 form 值快照，供 fillFromData 读取当前值做冲突判定（避免闭包陈旧）。
- `Field` 类型 = 8 字段联合；`FIELD_SETTERS` / `FIELD_GETTERS` 映射表统一按字段名读写 state。

### B.2 字段级增量回填（核心升级）
`fillFromData(d: PitchData, force: boolean)`：
1. 计算 `sig = pitchSignature(d)`；非 force 且 `sig === appliedPitchSig` → 直接 return（去重）。
2. `force` 时清空 `manualFieldsRef`。
3. 逐字段：
   - 若 `force` 或字段**不在** `manualFieldsRef` → 用 `d[field]` 更新该 state。
   - 若字段在 `manualFieldsRef`（用户已手动改）且 `d[field]` 与当前 `formRef` 值不同 → 记入 `conflicts`，**保留用户值**。
4. `setAppliedPitchSig(sig)`。
5. 有冲突 → `toastInfo(conflictToast, 列出冲突字段)`；无冲突 → `toastSuccess(parsedToast)`。

### B.3 用户手动编辑保护
- 每个字段 input 的 `onChange` 调用 `markManual(field)`（把字段加入 `manualFieldsRef`）后再 `setField(field, value)`。

### B.4 自动保存（与 v1 一致 + 合并手动值）
- 自动 effect 检测到新签名 → `fillFromData(data, false)` → 构造 `merged`：逐字段 `manualFieldsRef.has(f) ? formRef.current[f] : data[f]` → `UpdateNovel`（title/description/genre）+ `persistPitchPreferences(merged)` → invalidate `novels`/`preferences` → `toastSuccess(autoSavedToast)`。

### B.5 「采用全部建议」按钮（替换原「重新解析对话」）
- 新按钮「采用 AI 建议」→ 取最新助手消息 JSON → `fillFromData(data, true)`（force 清 manual，全量覆盖）→ 立即自动保存 merged。
- 原 `handleReparse`（force 重解析）保留逻辑但重命名为「采用 AI 建议」，文案更新 i18n。

### B.6 解析健壮性
- `extractPitchJSON` 保持 fence→整段→片段三级搜索；`stripPitchJSON` 保留。
- 新增：从最新一条助手消息向后搜索（已是）；若消息内含多个 JSON 块，取**最后一个完整**块（避免取到中间草稿）。

### B.7 i18n 变更
- 新增 `bookpitch.conflictToast`（"以下字段 AI 有新建议但已被你手动修改：X、Y；可点「采用 AI 建议」覆盖"）。
- `bookpitch.reparseBtn` 文案改为「采用 AI 建议」（`adoptAllBtn`）。
