## 00:27 dev 忽然白屏 —— 根因是 Wails dev 的 localhost 双栈绑定错配（按用户选择仅冷启动恢复，未改配置）

**现象**：21:00 冷启动的 dev 跑了 3.5 小时后，00:27 前端忽然白屏。

**结论：不是代码问题、不是昨晚「后台自动修复下线」那次改动、不是 watcher 失活、不是渲染进程崩溃。**

### 决定性判据（curl 加 `--noproxy '*'` 排除 curl 自身代理干扰）

```
http://127.0.0.1:34115/   → 200        （Wails dev server，只绑 IPv4）
http://[::1]:34115/       → 超时失败
http://127.0.0.1:5173/    → 超时失败
http://[::1]:5173/        → 200        （Vite 8，只绑 IPv6）
```

Wails dev 让 WebView2 加载 `http://localhost:34115` 并由 wails 转发到 Vite 的 `localhost:5173`，两个服务分别只监听一个 IP 栈。`localhost` 在 Windows 上的双栈解析优先级会变（DNS 缓存刷新 / 网络切换 / 渲染进程重建），某一侧重载解析到不匹配的一侧 → 页面取不到资源 → 纯白而不报错。佐证：到 5173 的 TCP 连接只剩一条 `TimeWait`，HMR 长连接已断且未重连。

**排除项（逐项实证）**：
- 后端健康：`novelgo-dev` PID 2428 存活，00:30 仍在正常写 SQLite、跑完 statesync（`run_subagent` elapsed 295826ms success）。
- WebView2：18 个 `msedgewebview2` 进程全部 `Responding=True`，主渲染 319MB，StartTime 仍是 21:00:59 那批（无崩溃重启）；Go 467MB / Vite 228MB，非 OOM。
- Vite：`/`、`/src/main.tsx`、`/src/lib/wailsjs/go/app/App.js` 全部 200 且正常编译。
- 源码：`frontend/src` 自 21:02:19 后 3.5 小时零改动，`git status` 干净；日志里零 JS error / panic / HMR error / `Rebuild triggered`。
- 重建 exe size 与旧版字节一致（79769313），也是「源码没变」的佐证。

**两个不是根因的观察（勿误判）**：
- `build/bin/novelgo-llm.log` 从 00:10 起密集刷 `llm stream idle watchdog fired, idle=9m`，看着像流全卡死；但 10-26 历史日志同样成片存在（当时是 3m 口径），是思考模型流结束后 response body 延迟清理的迟到 WARN，属于既有噪声。

## 03:15 更正：00:27 的白屏根因推断被证伪，已做配置根治（用户「请继续执行任务」）

**先纠正**：00:27 那节写的「Wails dev 让 WebView2 加载 localhost:34115 并转发到 Vite 5173，双栈解析漂移导致取不到资源」是**错的**。34115/5173 各绑一个 IP 栈是事实，但窗口资源根本不经过这两个 TCP 端口，所以「转发失败」不成立，冷启动当然无效 —— 用户 03:15 反馈「重启后 dev 桌面依旧白屏」，00:47 那次冷启动同样没修好（当时只核了 34115 对 curl 返回 200，属假恢复）。

### 真实链路（Wails v2.16 源码实证）

- `internal/frontend/desktop/windows/frontend.go:40`：`const startURL = "http://wails.localhost/"`；`:613` `AddWebResourceRequestedFilter("*", ALL)`；`:635` `processRequest` 由 Go 端 `f.assets` 喂资源。窗口导航的是 **`wails.localhost`（80 端口）**，靠拦截供资源，**不走 34115/5173**。
- WebView2 缓存里 161 个 URL 全是 `http://wails.localhost/...`（含历史 `/assets/index-*.js`），佐证窗口用的就是这个虚拟主机名。
- `cmd/wails/internal/dev/dev.go:130` 初始构建恒 `IgnoreFrontend=true`；`app_dev.go` 从 embed FS 推断 `assetdir` 后 `assetConfig.Assets = os.DirFS(frontend/dist)` —— 运行时读磁盘 dist，不是二进制内嵌。二进制里 `index-BQMedJJN.js` 唯一且与磁盘一致，9 个首屏资源在 34115 上全 200，说明**资源不缺**。
- `wails.json` 缺 `"frontend:dev:serverUrl"`；Wails 官方模板 `pkg/templates/base/wails.tmpl.json:8` 默认是 `"auto"`，`internal/project/project.go:143` 的 `IsFrontendDevServerURLAutoDiscovery()` 判 `== "auto"`。缺这一行 ⇒ 不启用外部 dev server ⇒ 34115 返回的是**构建产物** index.html（`/assets/index-BQMedJJN.js`，无 `/src/main.tsx`、无 `/@vite/client`），5173 虽启动但零消费。
- 拦截未生效时 Chromium 会去连 `wails.localhost:80`；实测 `http://wails.localhost/` → `::1:80` 与 `127.0.0.1:80` 均 Connection refused ⇒ 纯白、无 JS error、无 Established 连接。与观测吻合：窗口存活、渲染进程 Responding、缓存里无当前构建资产条目、到 34115/5173 的 Established = 0。

### 根治（2 文件，4 行新增）

- `wails.json` 补 `"frontend:dev:serverUrl": "http://127.0.0.1:5173"`（显式 IPv4，不用 `auto`，避免解析 Vite 输出的不确定性）。启用后 `app_dev.go:141` 换 `NewExternalAssetsHandler`、`Assets=nil`，dev server 反代 Vite 并注入 wails runtime，窗口走**真实 HTTP**。
- `frontend/vite.config.ts` 的 `server` 补 `host: '127.0.0.1'`，与 externalURL 和 34115 统一 IPv4。
