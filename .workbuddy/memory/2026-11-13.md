## #115 P0：章节检测「点了没作用」根因与修复（提交 5d2ce754）

### 用户现象
改稿后点「重新检测本章」或「启动检测」，都弹绿色提示「本章检测未完成（详情见日志），可稍后重新检测」；L0/L1 结果与修复前无变化，观感是按钮无效。

### 真因（日志 + 代码双证，不是供应商问题）
- `app/handler.go:516/508`、`app/editor_feedback.go:81` 三处后台链路用 **空 `agent.RunOptions{}`** 调 `RunSubAgent`；`RunSubAgent` 原样复制 parentOpts.Model，`agent.Run` 入口 `Model == nil` 立即返回 `agent: Model is required in RunOptions`，被 `FriendlyError` 兜底成「对话出错，请重试」。
- 日志实锤：`chapter-ci 子 Agent 派发失败 → 章节检测执行失败`，20:58/23:26/23:47/01:18/01:21/01:25 全是同一条。**章节手动检测的 L1 从未真正跑过**；P3 新增的完成事件只是把原本静默降级显示出来，用户才看见。
- 数据倒退：失败时 `RunChapterCIForChapter` 仍 `UpsertL1(l1_status=skipped)`，而 `UpsertL1` 的 `DoUpdates` 含 `l1_findings`，会覆盖成空。第4章 (id 2909) 被清成 `skipped` / `l1_findings=""`（01:25:02）；只有 `RecalcChapterL0FromDisk` 是真做了。
- 反馈层错：失败用 `toastSuccess`（绿色 ✓）+「详情见日志」（用户无日志入口），叠加点击时「已重新发起」，双条叠加。

### 修复（P0 全修，用户确认）
- 新增 `app/background_agent.go`：**后台子 Agent 模型单源**。`backgroundRunOptions()` 每次派发现取 `settingsSnapshot().SelectedModelKey → parseModelKey → llmClient.ProviderModel`，构造 `Model/ProviderName/ReasoningEffort`；`runBackgroundSubAgent` 是三条链路唯一派发入口。`errBackgroundModelUnavailable` 为可判定哨兵。
- 三处接线全部改为 `a.runBackgroundSubAgent`（chapterci / statesync / editorfeedback），保持 chat 主链路不变。`settingsSnapshot()` 加 nil 保护。
- `internal/mcp_tools/chapter_ci.go`：派发失败 / 回执坏 **不再 upsertL1**，仅记日志并返回错误，保留上一轮 checked 发现项与状态。`internal/quality/contract.go` 新增 `ErrL1ReceiptNotFound` 哨兵（ParseL1Receipt 末尾返回），注释中的「静默降级」口径同步改掉。
- 失败分类：`app/background_agent.go` 的 `classifyChapterDetectError` 归 `model / receipt / llm` 三类，包一层 `chapterDetectError`（实现 `DetectReason()`）；`internal/pipeline/detect.go` 用 `chapterDetectFailureReason` + `errors.As` 取码，`chapter_detect_done` 事件在 `!ok` 时带 `reason`（不解析错误文本、不传 LLM 原文）。
