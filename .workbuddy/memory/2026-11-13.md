### 技能价值结论（可证伪事实）
- 写章技能是**静态**的：`buildWritingSkillBundle` 只在命中 `next` 时触发（`app/slash_command.go:208-225`），输入仅章号/任务卡/`RhythmTemplate`/消息文本（`writing_skill_conditions.go:42-67`），**不读 finding、不读上一章检测结果、不读质量档案**。每章同一套：固定 3 技法 4,946 rune + 最多 2 个条件技能 3,000 + `next` 2,433 ≈ 7.4k–10.4k rune。
- 技能正文与检测器**不同源**：技能给「前 1000 字法则 / 每 800 字微钩子 / ≥3 Try-Fail / 第一句出事 / 开篇最炸」（平台卡与方法论），检测器用 `openingSlopeWindowRunes=500` rune、`openingSlopeMinRise=5.0`、`tensionSegTargetRunes=400`、`pacingDragMinRun=3` 及冲突/动作/短句词表（`internal/quality/tension_checks.go:17-22`）。写作侧 system 与检测同源的**只有单章字数**（`chapter_words.go:186-190 SystemLine`），其余零成文约束。

### `opening_slope` 根因（不是模型能力问题）
- 判定 `rise = max(窗口内后续段 Tension) − 首段 Tension`，`rise < 5.0` 报（`tension_checks.go:73-97`）；窗口 `StartRune<500`、分段按 400 rune ⇒ **真实语料窗口恒 2 段**（31/31 章），判定实为「第 2 个 400 字段 vs 第 1 个 400 字段」，#114 把「末段→max」在真实语料上差异 0 章（该修复无数值效果）。
- 真实落库 L0 曲线 31 章复算：rise −6.5~12.2、mean 0.18、median −1.3，**25/31（80.6%）不达标**；可达（样本 A 17.1），故**不属于 beat_gap 那种数学不可达**，而是「阈值未用真实语料校准 + 方向与写作规范相反」。
- **方向冲突**：`opening-chapters.md:51,54`「冷开场/第一句出事/前 500 字爆点」、`opening_hook` 双窗口信号词检查都要求首段高信号；判定却要求首段低、后段更高 ≥5.0。复刻样本 D「开篇炸/后文平」= **−17.1 必报**。满足 `opening_hook` 往首段堆冲突词，反而让 `opening_slope` 更不可能达标（两个检查互相打架）。
- 处方 `prescription.go:128-145` 阈值同源但**只给语感级动作**（无段位/字区间/数字），对比 `CheckBeatGap/CheckBeatDensity` 已有 `beatSegmentDiagnostics`/`beatActionHitsNeeded`；`tension_block.go:115-123` 仍按「末段−首段」渲染，且 `EffectiveTensionCurve` l1 优先 ⇒ l0（首段 23.29、命中率 80.6%）与 l1（首段 46.14、命中率 27.6%）两套曲线，界面同时显示「不足」与「达标」。`l0_verify.go:130-132` 自己承认曲线口径是粗粒度近似。
- 判官 `review/score.go` 无独立公式，只复述处方（`buildUserPromptWithPrescriptions`）；failed 记录里的「0.0 < 5.0」来自处方 `Current`/`Target`，不是二次计算。
