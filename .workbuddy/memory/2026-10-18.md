## 死循环中断诊断（"检测到重复调用循环，已中断对话"出现两次）

- 日志位置：`build/bin/novelgo.log`（dev 运行日志，落盘于 `internal/logger/logger.go` 的 `novelgo.log`）。
- 真相纠正：**触发点是主 agent（agentType=main），不是 statesync 子 agent**。报错从 `app/chat.go:220` 抛出，turn 内 `subTaskID=""`。
- 出现两次 = 两个独立对话轮各中断一次：turn 39 @02:03:11、turn 41 @02:08:11（中间 turn 40 正常无 ERROR）。
- 两个 turn 调用序列病态且一致：edit → get_chapter_list×2 → read×2+get_chapter_list×2 → 一批 get_*(characters/story_arcs/locations/reader_perspective/timeline) → edit 再润色 → get_chapter_list×2（触发轮）。**整段 0 次维护写工具**（update_character / create|update_timeline_entry / create|update_reader_perspective_entry / create|update_story_arc 均为 0）。
- 根因：edit 结果注入了"请执行维护操作"提醒（log 可见），主 agent 被要求做状态维护，却卡在只读验证环（反复 `get_chapter_list` 且用相同参数 `{"size":2}`），始终没调写工具。`isStuckLoop`（safety.go:66）命中：最近 4 轮模式 ≤2 种 + 当前轮全只读 + loopCount≥4。
- 维护写工具本身都在 `mainAgentTools`（identity.go:20-27），**不是缺工具，是 agent 行为卡死**；维护永远没做完 → 下一轮继续同样死循环（所以出现两次）。影响：第18章《堵口》改了 2 次但角色/时间线/读者认知/故事弧全未更新。
- 修复方向：A=把"写后维护"改交 statesync 子 agent（statesync 本就干这个，turn 37 成功跑过 create/update_timeline_entry）。B=维护提醒里明确"别重复 get_chapter_list，直接调四个写工具"。C=守卫加固（最近 4 轮含写工具即豁免，防假阳性）。
- **方案 A 已落地（本次）**：发现后端早已存在自动派发——`scheduleStateSync`（`rw_tools.go:904`，debounce 6s）→ `runStateSync`（:922）在每次章节正文 edit 后自动 `RunSubAgent(statesync)`，statesync 子 agent 白名单已含全部维护写工具。因此冗余的"注入提醒让主 agent 自循环"正是死循环根因。改动：
  - `rw_tools.go:549-564`：把 full_replace 长文后注入的"请执行以下维护操作（4 项写任务）"提醒，改为说明"后台已自动派发状态同步子 Agent，你无需手动维护，直接汇报即可"——消除主 agent 只读确认环。

  - `go build ./...` 全量通过（CGO 工具链）。
