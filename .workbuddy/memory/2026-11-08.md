## #102 台账 alive 不可写导致巡检修复转人工（工具面 + 派发面）

### 报障与根因
- 用户截图：巡检 T1「角色 #121 赵彦 alive=1 与第 2 章正文死亡事实矛盾」→ 第一次修复只改了 description/personality → 复验判「修复只改了一半」→ 第二次让聊天窗口 LLM 修改，LLM 如实申报 `skipped 转人工` 并给出 `UPDATE characters SET alive=0 WHERE id IN (121,126)`、T2 疤脸 #126 同款。
- **结论：系统设计缺口，不是 LLM 修复不了**。LLM 准确定位根因、核对白名单边界、给出 SQL 与派生建议，且没有谎报闭环。
- 证据链：`internal/character/types.go:41` `Alive *bool ... default:true`（迁移把存量角色全回填「在世」）；`mcp_tools/character_tools.go` 的 Create/UpdateCharacter*Args 只开放 name/description/personality/abilities；`base.go:305` `DisallowUnknownFields` 连偷偷传 alive 都拒（本意防篡改 id/novel_id/is_current，不能放开）；主 Agent 与 statesync 白名单（agentcfg/identity.go）均无写该列的工具，statesync prompt 却要求「角色状态变化 → update_character」。而 alive 被 L0（quality/l0.go:231）、plan_check、invariant_check、巡检语料 dumpLedgers 当事实源读 → 正文明写已死、alive 永远 1 的系统性漂移。一整片 D1 结构化列（gender/faction/sealed/voice_traits…）同样无 LLM 写入面，alive 只是第一个被硬指标读出来暴露的。
- 「转人工」机制本身正确（fixReceipt 契约允许 skipped 带原因；`verifyEscalateAfter=3` 自动升级；detect.go:254），但「字段静态不可达」不该空转两轮修复 + 两轮复验才触发。

### 本轮修复范围（用户选「工具面 + 派发面」，不动 statesync 架构）

## #103 第三层：statesync 生死态派生 + 人工入口

### 需求
- 用户：做第三层（statesync 派生 + 人工入口）。目标：alive 不再靠人工/LLM 自觉维护，每章写后自动从正文派生，并给作者纠正误标 / retcon 的入口。

### 实现（勿回退）
- 新增 `internal/character/alive_derive.go`：`ScanDeathMentions` 高精度召回「角色名/别名 + 紧邻完成态死亡谓词」（长名优先、单字名跳过、同句否定/假设/转述/假死/疑问/比喻后缀排除、他人所有格「的」不允许）；`DeriveAliveFromChapter` 单向 true→false、幂等、按 novel_id 隔离、写走 GORM Save 自动进 ledger_change_history。
- **人工裁决优先**：角色最后一次 alive 履历 `source != auto`（author/retcon）时派生跳过，避免「作者刚纠正误标，重跑同一章同步又被同一句正文标死」。履历表缺失/无记录时保护不生效，派生照常（旧库不被阻断）。
- `internal/mcp_tools/state_sync_alive.go`：派发前读本章正文（正文不在 DB，走 `git.ReadFile(novelID, git.ChapterPath(chapterID))`）→ 派生 → 把命中名单 + 原文摘录注入 instruction 供 LLM 复核/补漏。db=nil / 正文缺失 / hook 拒写（已钉住条目 guardPinnedAuto）都降级且非阻断。
- `RunStateSyncForChapter` 签名加 `db *gorm.DB`（两个调用点：`rw_tools.runStateSync` 传 tc.DB、`app/handler.go` 的 S0 bridge 传 a.db）；`stateSyncAgentSystem1` 增「生死态硬指标」与「已死不复活」。S0 批量对齐会顺带修历史漂移。
- 人工入口：app `Create/UpdateCharacterInput` 加 `Alive *bool`（nil=完全不碰该列，避免 PUT 把已标死写脏；非 nil=显式设置，允许 retcon 复活；MCP 工具仍单向）。同步 wails `models.ts` 类型。前端 CharacterListView 编辑表单加「在世/已故」下拉 + retcon 警示，主视图卡片与侧边栏加「已故」徽标，zh/en i18n 同步。
- **精度口径**：宁漏勿误（本地只召回，LLM 复核补漏），绝不从自由文本猜生死；gap 不得吞「已」（否则「，已死」漏报）、后缀排除必须用「谓词+后缀」整串比对（否则「死了心」漏排）。
