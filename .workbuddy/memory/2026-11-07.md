报障：「签约体检修复了一个问题，修复下一个问题的时候前一个问题又变成了待确认状态」。四线对因：
1. **主凶 E 系换血**：`LandTensionTickets`→`ReplaceIssuesByPrefix` 按章前缀整删整插，任何章保存（含修复正文落盘）把该章 E 系工单全落 pending。修复=换血保留用户流转状态：`matchCarryRows` 两遍匹配（键+Area 精确→Area 兜底，旧单每条只消费一次）+`carryIssueWorkflow` 整组继承（Status/SkipReason/VerifyReceipt/VerifyAt/VerifyAttempts/Note/PreVerifyStatus/Round/CreatedAt）；发现身份=Area（检查项），desc/level 走刷新语义。`ReplaceIssues`（整批替换）刻意不动——issue_test.go 锁死「新体检=新问题清单」语义。

3. **帮凶复验回退**：`RecordIssueVerifyUnverified` 原无条件写 pending→已修复（待复验）被一次供应商超时打回「待确认」。修复=`pre_verify_status` 快照列（UpdateIssueStatus 置 verifying 时事务内原子捕获，重复复验不覆盖最初快照）+`verifyRestoreStatus` 恢复语义（fixed/confirmed/pending/rewrite/skipped/retcon 原样，空/fixing/verifying/终态→pending 兼容口径）；`RecordIssueVerifyUnverified` 只动 verifying 行（其余只写 note 防回退已收口状态）；`resetVerifyingRows` 逐行条件更新（id+status=verifying 围栏）；`ResetStuckVerifying(ctx,novelID,runID)` 加 runID 收窄（顺修跨 run 互踩）。rejected→pending 保持（明确未通过=退回待修）。

### 坑
- `go build` 不认 `--build-tags`（那是 golangci-lint 旗标）：编译/vet 用 `-tags webkit2_41`，golangci-lint 用 `--build-tags webkit2_41`。
- Bash 工作目录跨会话不持久：npm 闸门用 `npm --prefix frontend run ...`，或先显式 cd（根 package.json 只有 build/dev/add，lint 在 frontend 下）。
- runIssueFixTickets 测试桩里翻工单状态要走 `StartIssueFixTickets` 全量语义（真实并发点击路径），断言经变量回收——require 不可跨 goroutine（runLedgerFixTickets 分组 goroutine 里执行桩）。
