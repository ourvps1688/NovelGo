## 书架空自动建书后灵感未带入 chat（最终修复，已提交）

用户反馈：空书架点「开始」已能自动建第一本书，但灵感/kickoff 对话没有发到聊天面板。
- 根因：`handleStart` 建书 + `switchNovel(id)` 后用 `setTimeout(0)` 取 `useChatLaunchStore.getState().send` 发 kickoff；但此时 `ChatPanel` 尚未用新 `novelId` 重新注册 `send`（旧闭包含旧 novelId），消息发到错误/过时上下文而丢失。
- 最终方案：改走"待发消息 store" `pendingKickoff`，由 `ChatPanel` 在新 novelId 上下文就绪后自行发送，彻底规避闭包竞态。
  - `useChatLaunchStore` 新增 `pendingKickoff: string | null` 与 `setPendingKickoff(content)`。
  - `BookPitchWorkflowView`：建书 + `switchNovel` 后，把格式化好的 kickoff（仍用 `t("bookpitch.kickoff", {idea})`）写入 `setPendingKickoff`，移除 `autoKickoffIdea` state 与 `setTimeout(0)` effect、并去掉已无用的 `useEffect` 导入。
  - `ChatPanel`：新增订阅 `launchSend = useChatLaunchStore(s=>s.send)` 与 `pendingKickoff = useChatLaunchStore(s=>s.pendingKickoff)`；`useEffect([pendingKickoff, launchSend, selectedModel])` 在 pending 非空、且 `launchSend` 已用新 novelId 重新注册、`selectedModel` 已恢复后才 `setPendingKickoff(null)` 并 `launchSend(pendingKickoff)`。三依赖确保消息不会因 send 仍是旧闭包或模型未就绪而丢失。
- 验证：`tsc`/prettier/i18n:check/theme:check/eslint(0 error)/vite build（输出到 `distN` 后 `git clean -fd` 清理）均通过。
- 注：空书架自动建的第一本是"孵化讨论场"，标题取灵感前 20 字、简介前 200 字；用户仍可回到「采纳方案并建书」表单以正式书名覆盖/新建。
