## P0-1 reranker 离线收益评测（2026-11-01，commit 91d8f3c5，已推 origin/master，0 0 同步）

用户要求：先评测 reranker 收益，若是负优化就不必做。

新增 `internal/rag/reranker_eval_test.go`（`//go:build cgo && eval`，不进 CI）。合成中文小说语料（5 章/16 查询：10 易含实体原词 + 6 难语义改写；含植入事实、跨块边界难点、共享高频词干扰章节），走真实 `VectorStore.Search`+`rag.Rerank`/`MMRRerank`，对比 cosine/MMR/reranker 三档 Recall@K 与 MRR，按 overlap 0/50/100 扫描。本地实跑 16.7s。

结果（reranker=bge-reranker-base，279MB 模型已加载）：
- Recall@K：K≥3 三档均 100%（cosine/MMR/reranker 持平），K=1 时 cosine 0.875 / reranker 0.750（reranker 更差）。
- MRR：cosine 0.938 / MMR 0.938 / **reranker 0.835**（reranker 最差）；易查询 reranker 0.803 vs cosine 0.900，难查询 reranker 0.889 vs cosine 1.000。
- overlap 扫描对召回无影响（干净语料下边界非瓶颈）。

结论：**疑似负优化**——reranker 在余弦已饱和的干净短中文 chunk 上无救援反而引入噪声（MRR 下降、top-1 退步）。局限：语料小且干净，真实章节（更多 chunk、主题相近、歧义 query）可能是 reranker 真正发力场景。

下一步决策（待用户定）：①在真实章节语料复核；②若仍无增益，回退 P0-1 接线（删 `app/handler.go` 的 `InitReranker` + 4 处消费方回落 `MMRRerank`），省 279MB + 每 query 推理延迟（V2-D 多 query 成本被放大）。P0-2 的 MMR 回落已足够提供多样性重排，移除 reranker 不影响优雅降级不变量。

## P0-1 reranker 真实数据复核 + 回退（路径 A，2026-11-01，commit 8b769042 评测脚本 + 66805424 回退，已推 origin/master 0 0 同步）

## P1-2 embedding 模型升级 决策：放弃（2026-11-01，仅文档/记忆变更，无代码改动）

用户确认：按 P0-1 评测结论，P1-2（升级 1024 维模型 + 重建向量库）也没有必要做。

放弃理由（写进 plan §10.4）：
1. reranker（提升一阶 embedding 的唯一二阶消费方）已证伪回退，改善一阶向量无二阶承接、缺收益闭环。
2. 真实评测给出当前 512 维 baseline 已达标（整体 MRR 0.679、跨块 0.926），**无证据 embedding 维度是瓶颈**。
3. 跨块漏召是 reranker 产物（0.926→0.299）而非维度问题；单条超长截断已由 P1-1 补掉——两者都不指向「需要更大维度」。
4. 维度变更须全量重建向量库（所有 novel 的 vec 表），large 体积×2、低端机更慢，与「不得影响写作/功能」硬约束冲突，成本高风险，无收益证据不该启动。

代码现状：P1-1 已把 `embeddingDim` 常量集中，若未来确有瓶颈证据可一键立项重建，无需此刻预支成本。
文档变更：`docs/onnx-enhancement-development-plan.md` §10.2 标注「决策：放弃」+ 新增 §10.4 决策记录 + §10.3 进度表校正（P0-1 已回退、P1-2 已放弃）+ §9 决策建议校准；`MEMORY.md` 两处「P1-2 待授权」→「已放弃」。本次仅文档/记忆，无业务代码改动，未提交（属记忆类，可并入后续 `chore(memory)`）。
