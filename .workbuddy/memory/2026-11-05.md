## 复验终极提速落地（09c29617，已推送 0 0）

用户痛点「复验环节太慢特别费时间」根治。根因：逐工单**串行** × 每工单一次
**12 轮 agent 循环靠工具现读证据**（read 逐章 + get_* 读台账），思考模型单工单
2~10min，N 张叠加半小时以上；而证据本可毫秒级本地预取（取数与推理未分离）。

三招组合（5 文件 +471/-78，语义契约零破坏，预期提速约一个量级）：
- **语料预取内联**（verify_corpus.go）：工单作用域章正文（章帽 8000，掐头尾
  2/3+1/3 保尾部修复点）+ 紧凑台账快照（8k 帽）由后端批量取好内联提示词
  【本次复验语料】，明示禁止工具往返——单次调用从最多 12 轮取数推理压到一轮
  出回执；verifyMaxTurns 12→3，新增 verifyMaxTokens=24k 压思维膨胀；
  单批语料帽 40k（沿巡检超时复盘体量纪律，远低于 44k 实测成功线）。
- **批量合验**：verifyPrompt/回执契约原生多目标，verifyBatchSize=4，调用次数
  N→⌈N/4⌉；回执逐 id 拆分、未提及单单列未确认（绝不静默全过）。
- **批间有限并发** verifyBatchParallel=2 + 落库单 goroutine 串行收口（避
  SQLite 并发写锁）；L0 快路径先行串行（机械类免 LLM 不变，其台账装配 DB 读
  不进并行段）。

契约不变量全保留：人工触发零自动派发、3 次明确未过转人工（escalate）、
CancelIssueVerify 可取消、有界超时、逐工单故障隔离语义（批失败=整批未确认
留待下轮，粒度注释明示）、失败分层 note 三档（措辞「单工单」→「单批」）。
signability-verify.md 补「语料已内联则禁工具」方法论（回执格式串契约不动）。
新增 3 测试（批量调用次数/语料内联/纯函数边界），pipeline 172s + 全量
go test 绿，四道闸绿。
