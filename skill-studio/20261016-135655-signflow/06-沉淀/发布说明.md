> 形态：NovelGo 内置编排技能（单文件 `.md`，纯 LLM 提示词，免脚本/references）

## 1. 这是什么

一个 **`mode=manual`、`category=系统`** 的内置技能，把 NovelGo 已有的 3 个签约专项技能：

- `story-blueprint`（auto，宏观蓝图）
- `worldbuilding-design`（auto，世界/设定）
- `signability-audit`（manual，签约体检）

**编排**成一条引导式闭环：

```
阶段 0 现状诊断 → ① 规划蓝图 → ② 世界设定（按需） → ③ 写作推进 → ④ 签约体检 → ⑤ 闭环回修
```

它**只编排、不重写**——不复制任何专项技能的方法论，不直接落库任何数据，只负责：告诉用户现在在哪一步、下一步该调哪个技能、给什么输入、预期什么产出、体检出问题后回哪修，并全程引用本书题材卡约束。

## 2. 解决的用户痛点（P2-3）

| 旧状 | 新态 |
|------|------|
| 3 个签约技能都能跑，但用户只能聊天打字触发或在「技能矩阵」里零散发现，**没有引导式闭环** | 一条六阶段引导闭环，阶段清单 + 目标 + 完成判据 + 调用技能名 + 题材卡提示一屏看清 |
| 不知「下一步该调哪个、输入什么、产出什么」 | 每阶段明确「下一阶段触发词 + 调用哪个技能」结构化小结（C6） |
| 蓝图/设定/体检各自为政，**无回修回路** | 阶段⑤ 把每条 P0/P1 映射到「回哪阶段 + 调哪个技能」，形成「体检→修复→复检」回路（C4） |
| 易陷入「写完才体检」滞后模式 | 阶段 0 现状诊断引导用户先规划、早体检 |

## 3. 验收（AC1–AC9）

边界 B1–B8 全符合（不重写/不落库/不替评分/不做 UI/不改 3 文件/不臆造/不越权/不抢单点）。

## 5. 已知设计约束（透明披露，非阻塞）

- **R1 签约体检偏好无专用回读工具**（仅 `upsert_preference` 写）：闭环修复不设计「读旧体检报告」步骤，靠「重新跑 `signability-audit`」实现复检，不静默带过。
- **R2 跨体检 diff**：暂无工具，列为可选增强，不在内核范围。
- **R3 `category=系统`**：经核查现有 taxonomy 无「流程」分组，归入「系统」与 `next.md` 等调度/元技能同桶，零新增分组。

## 6. 如何触发

- 用户主动进入（`mode=manual`）：在技能矩阵中选用，或在对话中命中 cue——「签约潜力」「签约工作流」「一书通盘规划」「蓝图到体检」「这本书能不能签」「编辑愿意签吗」等。
- 也可经 `/` 命令或聊天输入区触发；`useWhen` 已生成目录路由提示。
