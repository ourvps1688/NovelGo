# 世界观与设定设计

## 何时使用
用户说"设计力量体系""金手指怎么设""升级系统怎么搭""地图/势力怎么排""战力崩了""设定太水"时自动加载。

**对齐声明**：本书若已选题材卡，其「禁止漂移 / 金手指一致性 / 爽点密度」是设定边界。爽文卡已硬编码「金手指一致性：能力前后统一，不得为推进剧情临时无依据开挂或吃书」——设定设计须服从，且所有设定最终写入设定库以防吃书。

## 核心原则
世界观是**情节的舞台与冲突的源头**，不是设定集。判定一条设定该不该有，只看它是否：制造冲突、提供爽点、承载主题、或塑造人物。纯展示性设定一律砍。

## 工作流

### 1. 定锚点：世界围绕核心卖点转
先锁定本书核心卖点/主题（升级爽感？智斗？种田经营？），世界的一切围绕它运转。例：升级流的世界必须提供"清晰的力量层级 + 可被利用的规则漏洞（金手指）"；种田流的世界提供"可积累的产出链条 + 社群生态"。

### 2. 力量 / 能力体系设计（升级驱动型 ① 必备）
- **层级清晰**：有明确阶位、上限、瓶颈与突破条件，读者能画出"升级地图"。
- **金手指三要素**：① 独特性（一眼记得住）② 代价/限制（防止万能）③ 成长曲线（随主角变强而解锁新用法）。
- **规则可见可推**：采用"硬规则"思路（参考 Sanderson 硬魔法原则）——能力如何运作必须清晰，爽点来自主角**用规则反制对手**，而非作者降智配角。
- **服务于打脸/越级**：金手指的妙用应是"同级碾压、越级反杀"的引擎。

### 3. 势力 / 地图 / 生态
- 势力是冲突供给机（对手、资源、舞台），不是背景板；每个主要势力有清晰诉求与实力定位。
- 地图服务于"下一站去哪、对手在哪一层级"，不要为宏大而宏大。

### 4. 一致性自检
- 规则自洽：能力、代价、层级前后不矛盾。
- 平衡不破：金手指有代价，不会让所有冲突失效。
- 不踩题材卡禁忌（金手指一致性、禁吃书）。

### 5. 写入设定库（防吃书）
用 `upsert_setting` 固化核心规则与关键事实；用 `create_location` / `create_location_relation` 记录地图与势力关系；用 `create_timeline_entry` 记录世界史关键节点。后续写作以库为准，避免前后矛盾。

## 信号检查

| 症状 | 诊断 | 对策 |
|------|------|------|
| 战力崩坏、谁都能赢 | 缺清晰层级或金手指无代价 | 重做步骤 2：立阶位 + 给金手指限制 |
| 金手指万能、冲突全解 | 缺代价/限制 | 加使用成本或触发条件 |
| 设定堆砌、无冲突 | 把设定集当目的 | 只留服务情节的设定，其余砍 |
| 地图宏大但空 | 地图未绑冲突/对手 | 每个区域配势力与层级目标 |
| 前后矛盾/吃书 | 没入设定库 | 用 upsert_setting 固化并写作时查库 |
