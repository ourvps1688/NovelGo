# 作品外包装（Book Pitch）

## 何时使用
用户开新书、要起书名、写作品简介、选标签、定方向，或说"书名怎么起""简介怎么写""标签选什么""这本书卖点是什么"时手动调用（`mode: manual`）。本技能管**签约漏斗最前端的过滤关**——编辑/算法在翻开正文前，先看到的是「书名 + 200 字简介 + 标签 + 前 3 章」。外包装不过关，正文再好也进不了审稿池。

**对齐声明**：外包装须服从本书题材卡的「调性/禁忌」与平台约束卡的「签约口径」；二者给的是约束边界，本技能给的是"如何把边界设计成吸睛外包装"的方法。

## 为什么外包装定过签
- **算法关**：番茄/七猫的过签与推量由"书名/简介/标签匹配度 + 前 3 章完读"共同决定，外包装是召回与点击的第一道闸门。
- **编辑关**：起点/晋江编辑先扫书名与简介判断"题材契合 + 卖点清晰度"，再决定要不要读前三章。
- **读者关**：榜单与推荐流里，读者用 0.5 秒在书名+简介上做点击决策。

## 一、书名方法论（按平台差异）

| 平台 | 书名公式 | 范例逻辑 |
|---|---|---|
| 番茄 / 七猫 | 短狠直给，强钩子词 + 爽点词（≤12 字优先） | 《重生之都市狂医》《我在废土开超市》——身份/场景 + 爽点 |
| 起点 | 「名词：名词」或「身份 + 事件」的宏大感公式（可略长） | 《诡秘之主》《夜的命名术》——意象对仗 / 世界观钩子 |
| 起点女生 | 女主向「身份/金手指 + 反差」或「CP 暗示」 | 《嫡女贵凰》《退婚后我成了玄学大佬》——身份反转钩子 |
| 晋江 | 人设反差 / 关系钩子 / 文风感，避免过度剧透 | 《偷偷藏不住》《告白》《小敏家》——情绪/关系留白 |

**书名红线**（与题材卡一致）：
- 不得与已大火书高度撞名（混淆检索、编辑反感）。
- 不得挂羊头卖狗肉（书名承诺的爽点/类型，正文必须兑现，否则退订率反噬）。
- 玄幻/高武等须让读者一眼看出"力量体系类型"，悬疑须透出"谜题感"。

## 二、200 字钩子简介

结构（强钩子优先于平铺设定）：
1. **首句即抛钩子**：第一句给出最尖锐的冲突/反转/悬念（"重生归来，她把渣男送上了断头台"），而非世界观说明。
2. **中段给主角的"欲望 + 阻碍"**：主角要什么、被什么挡着、金手指/反差是什么。
3. **尾句留长线钩子**：一句暗示更大阴谋/身世/世界真相，勾出"想读下去"的欲求。

**分平台微调**：
- 番茄/七猫：简介前 30 字就要出现第一个爽点/冲突（完读逻辑前置）。
- 起点：简介可稍重世界观与主线野心，但仍须有主角钩子。
- 晋江：简介重人设反差与关系张力，避免剧透结局。

**简介红线**：不剧透大结局；不写"本文讲述了一个……"式说明书腔；不堆设定名词。

## 三、标签选型

- 标签 = 算法的检索与推荐入口，须与正文真实类型一致，宁准勿多。
- **主标签**（1–2 个）对齐题材卡分组（如 玄幻/都市/悬疑/言情）；**辅标签**（2–3 个）补卖点维度（重生/系统/甜宠/爽文/脑洞）。
- 平台差异：番茄/七猫标签偏"爽点/节奏"维度；晋江标签偏"CP/人设"维度；起点标签偏"世界观/流派"维度。
- 标签禁漂移：与题材卡「禁止漂移」同逻辑，选了的标签正文须兑现。

## 四、方向（主线锚点）

方向是用一句话锚定本书主线走向，让后续章节不漂移、不散。它比简介更"内敛"——简介对外吸睛，方向对内定盘。
- 公式：「主角在【世界/设定】中，以【核心欲望】为驱动，对抗【核心阻碍】，逐步揭开【终极谜题/成长弧】」。
- 例：「社畜重生回高考前，用未来记忆逆天改命，却在爬到巅峰时发现这场重生本身是一场实验。」

定型方向后：
- 后续章节应围绕方向推进，偏离需主动拉回；
- 与题材卡「禁止漂移」协同，方向是漂移的第一道防线。

## 五、一句话卖点（电梯演讲）

给编辑/读者 1 句话记住这本书的"差异化记忆点"：
- 公式：「当【群体/设定】遇上【反差/金手指】，主角【核心欲望】+【最大阻碍】」。
- 例：「当社畜重生回高考前，他用未来记忆把全家拖出泥潭，却发现自己重来一次仍是局中人。」
- 这句话应能用进简介尾句，也可作为本书"题材卡之外"的对外一句话定位。

## 六、外包装自检清单（diagnostic）
- [ ] 书名是否让目标平台读者一眼看出类型与爽点？
- [ ] 书名是否与正文真实兑现一致（无挂羊头）？
- [ ] 简介首句是否就是钩子（非设定说明）？
- [ ] 简介是否在 200 字内给出"欲望 + 阻碍 + 长线钩子"？
- [ ] 标签是否与正文真实类型一致、主辅分层清晰？
- [ ] 方向是否一句话锚定主线、可作为漂移防线？
- [ ] 一句话卖点是否能让陌生人 5 秒记住差异化？
- [ ] 外包装调性是否贴合本书题材卡、符合平台签约口径？

**任一未勾 → 重写对应项，再提交。`signability-audit` 的"书名简介契合"维度会二次核验。**

## 工具协同
- 用 `upsert_preference`（category=创作约束）固化"书名承诺 + 一句话卖点"，让后续章节不漂移。
- 若本书已选平台约束卡，起名/简介/标签须套用其「签约口径」参数。
- 外包装成型后，手动触发 `signability-audit` 做"书名简介契合 + 题材契合 + 平台适配"联合体检。

## 终稿结构化输出（必做）
当你与用户把外包装打磨到可签约状态、**准备交付时**，必须在回复的**最末尾**输出一段严格符合下方 schema 的 JSON，放在三反引号围栏里（语言标记写 `bookpitch`）。这段 JSON 会被前端自动解析并回填到「采纳方案」表单，因此字段必须完整、值必须是纯文本（不要带 Markdown 标记）。

```bookpitch
{
  "title": "书名（≤20 字，必备）",
  "description": "200 字以内的钩子简介（首句即钩子，必备）",
  "tags": ["主标签1", "辅标签2", "辅标签3"],
  "direction": "作品核心方向与主线一句话锚定",
  "genre": "题材（如：都市重生 / 玄幻 / 悬疑，可空）",
  "platform": "目标平台（如：番茄 / 起点 / 晋江，可空）",
  "style": "文风（如：爽文 / 治愈 / 暗黑，可空）",
  "oneLiner": "一句话卖点（电梯演讲式差异化记忆点）"
}
```

字段约束：
- `title` / `description` 必填且不可为空；其余字段允许为空字符串 `""`。
- `tags` 必须是**字符串数组**（若只有一个标签也写成 `["标签"]`）；不要用逗号拼在一个字符串里。
- 所有值都用简体中文（除非用户明确要其他语言）；不要包含换行、不要带 `#`/`*` 等 Markdown 符号。
- 只输出**一个**这样的围栏块，放在回复最后；围栏前后不要再加"以下是 JSON"之类解释文字。
- 若对话中存在多轮 JSON，以**最后一条完整**的为准（前端会取最新一轮）。

输出该 JSON 后，用一句话告诉用户：外包装已成型，右侧表单已自动填入，可直接点「保存书籍」。
