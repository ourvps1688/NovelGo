# 章节写后自检

## 何时使用
刚完成一个章节的写作或续写之后主动使用；或用户要求"检查这章""这章达标吗""自检一下"时加载。

## 工作流

写完一章后，**先不要汇报完成**，按下面的清单逐项核对，然后给出简短的自检报告。任何一项不达标，先修复再交付。

### 1. 字数门槛
- **以真实字数准，不要自己估算**：通过章节列表 / get_chapter 等工具返回的「· N 字」(word_count) 读取本章实际字数。系统的字数统计 = 中文字符数 + 英文单词数，比凭感觉估的准得多。
- **目标字数来源**：优先取本章大纲「基调与字数」里你写的预估字数；若大纲没写预估字数，默认基准 **2000 字**（爽文/脑洞类可在创作偏好里写更高目标，文学/细腻向可更低）。
- **判定**：实际字数低于目标的 **70%** 视为不达标，应扩写而不是交付；达到 70% 以上即算通过。不要用"必须 3000 字"这类固定死标准误杀正常篇幅。

### 2. 推进与功能
- 本章是否推进了至少一条主线（情节/关系/认知三选一），纯水文不过关。
- 章内至少有一个"状态改变"：主角处境、角色关系、读者认知三者必有其一发生变化。

### 3. 情绪流与爽点
- 检查情绪曲线是否有起伏：压抑→释放、危机→化解、铺垫→爆发，至少完成一次完整循环。
- 对照题材约束（若创作偏好中配置了"创作约束"）核对爽点密度：爽文章节至少 1~2 个明确爽点；非爽文题材检查是否有等效的"满足感节点"（悬念揭示、情感兑现、谜题推进）。
- 章末必须有钩子：新悬念、危机升级、反转预告三者之一。

### 4. 禁忌核对
- 无元引用（不得出现"读者""作者""本书""上文提到"等破墙表达）。
- 无现实人名、现实品牌、现实地名（架空名除外）。
- 无吃书：本章内容不得与已确立的设定、时间线、人物关系矛盾；引用设定前先查（可用 memory 检索或设定文件核对）。
- 主角处理符合题材约束（如爽文禁虐主、有仇不过夜）。

### 5. 正文格式核对
- 无「一、二、三、四」或「（一）（二）」类序号充当段落/小节分隔符——正文用叙事自然分段，不要给场景或情绪段强行编号。
- 破折号「——」未滥用：不替代逗号/句号，不在段落间密集连段；停顿用逗号或省略号，并列用顿号。

### 5. 一致性抽查
- 本章出场角色的名字、称呼、性格口癖与人物卡一致。
- 时间线连续：与上一章的时间、地点衔接无跳跃矛盾。
- 伏笔处理：本章若回收伏笔，确认伏笔登记过；本章若埋伏笔，确认足够隐晦且可回收。

## 报告格式

自检完成后用 3~6 行汇报：
- ✅/❌ 逐项结论（字数 / 推进 / 情绪流+爽点 / 钩子 / 禁忌 / 格式 / 一致性）
- 有 ❌ 的项：说明问题并**直接修复**，修复后再确认。
- 全部通过才向用户宣告本章完成。
