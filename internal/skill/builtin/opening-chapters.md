# 黄金前三章（Opening Chapters）

## 何时使用
用户开新书、写第 1/2/3 章，或说"开篇没吸引力""开头怎么写""前三章散""编辑会往下看吗"时自动加载。本技能管**开篇 1–3 章的过签力**，与 `story-blueprint`（宏观蓝图）、`scene-beats`（单场景节拍）、`plot-hook`（伏笔钩子）、`reader-immersion`（代入感）、`deai-flavor`（去 AI 味）互补，不替代。

**对齐声明**：开篇须服从本书题材卡的「开场抓手 / 章尾钩子 / 禁止漂移」；题材卡给的是约束，本技能给的是"如何把约束设计成杀手级开篇"的方法。

## 平台透镜（以活动平台预设卡为准）
若本书已在偏好选定「平台约束卡」（category=平台约束），以下参数覆盖本技能默认，且与题材卡正交：
- 首个冲突钩子窗口 `hook_window_open`：番茄≈300 / 七猫≈400 / 晋江≈800 / 起点女生≈800 / 起点≈1000 字——前 N 字内必出第一个冲突/异常/悬念，替换本技能默认的"前 1000 字法则"。
- 单章目标字数对齐 `target_chapter_length`（番茄 1200–2000 / 七猫 1000–1800 / 晋江·起点女生 2000–3500 / 起点 3000–4000）。
- `allow_setup_chapters = 否`（番茄/七猫）时，禁止纯铺垫章，每章必须推进或给甜头；`= 是`（起点/晋江/起点女生）时允许蓄力章。
- `paywall_aware = 是`（起点/晋江/起点女生）时，付费墙前一章须预留全书最大钩子位，强制拉满张力。
- 平台卡管「时序/节奏」，题材卡管「调性/禁忌」；冲突时平台卡赢在节奏时序、题材卡赢在内容禁忌；平台卡优先级高于本技能默认。

## 为什么前三章定生死
- **编辑视角**：网文编辑审稿常"滑前 3 章 + 扫爽点密度"，前三章没钩子直接弃。
- **读者视角**：起点/番茄/晋江前三章决定追读率，前 3 章流失即永久流失。
- **核心三角**：一篇能签的开篇必须同时成立——**代入感（读者黏进主角视角）× 钩子（不看完睡不着）× 甜头（立刻尝到价值）**。三者缺一则"能读但不过签"。

## 第一章解剖（冷开场法则）
1. **冷开场，不铺设定**：从"正在发生的事"切入，禁止以"世界观说明 / 主角独白自我介绍"开篇。把设定揉进行动与冲突（`worldbuilding-design` 的设定此时只应"泄漏"不"讲授"）。
2. **前 1000 字法则**：第 1 段就要有"异常 / 压力 / 欲望"。读者前 1000 字没读到任何悬念或利害关系，跳出率陡增。
3. **主角欲望即时呈现**：用具体行动或处境让主角"想要什么"可见（参 `character-design` 的"欲望清晰化"），而非用形容词陈述性格。
4. **首个冲突 / 压力源**：第 1 章内必须出现对抗——外力压制、反派现身、或命运缺口。无冲突的开篇是流水账。
5. **POV 黏着**：开篇死守主视角（`reader-immersion` 的"限制全知"），禁止镜头乱切。
6. **信息节流流**：设定、背景、人物关系用"喂一口用一口"，禁止前三千字倾倒（`deai-flavor` 的 tell-not-show 红线在此最敏感）。

## 第二、三章：升级 + 首个甜头 + 长线钩子
- **冲突升级**：第 2 章把第 1 章的压力翻倍，让主角陷入更深的局。
- **给首个甜头（爽点）**：第 2–3 章必须兑现一次读者期待的"爽"——逆袭、打脸、金手指首秀、情感确认。甜头越靠前，留存越高（对齐题材卡"爽点密度"）。
- **埋长线钩子**：在第 3 章末尾抛出一个"跨卷级"疑问（身世、敌人真面目、世界真相），与 `story-blueprint` 的"全局悬念布局"呼应。

## 章尾钩子设计
每一章（尤其前三章）结尾用"悬念 / 反转 / 新威胁"收束，而非"平稳落幕"。对齐 `plot-hook` 与题材卡「章尾钩子」——钩子不是"下回分解"的套话，而是让读者"必须点下一章"的认知缺口。

## 题材差异化开篇（按题材卡分组）
> 以活动题材卡为最高约束；以下为各流派的"开场抓手"范式，可混合。

| 流派 | 开篇范式 | 首个甜头示例 |
|---|---|---|
| 玄幻 / 高武 / 修真 | 金手指首秀前的"被压制"处境 → 绝境触发能力 | 越级反杀、以弱胜强 |
| 爽文 / 历史争霸 | "压抑/受辱"开局 → 立刻反杀（禁虐主、有仇不过夜） | 打脸、夺回尊严 |
| 种田 / 日常 / 美食 | 现实秩序被打破（穿越/破产/系统） → 用经营破局 | 第一桶金、邻里改观 |
| 悬疑 / 推理 | 抛出不可解的谜题 / 尸体 / 反常事件（禁无敌主角） | 第一个推理突破 |
| 女频言情 / 甜宠 | 关系张力开局（误认/契约/重逢）或身份钩子 | 第一次心动 / 反差揭晓 |
| 重生 / 复仇 | 带着记忆的"已知危险"切入，信息差即钩子 | 避开原悲剧、提前布局 |

## 开篇自检清单（diagnostic）
- [ ] 前 1000 字有"异常 / 压力 / 欲望"之一吗？
- [ ] 读者能在第 1 章结束时说清"主角想要什么、被什么挡着"吗？
- [ ] 第 1 章内有真实冲突吗（非内心戏）？
- [ ] 前三章是否各有一个章尾钩子（非套话）？
- [ ] 第 2–3 章是否兑现了至少一个甜头 / 爽点？
- [ ] 是否做到了"设定喂一口用一口"，无大段说明？
- [ ] 开篇调性是否贴合本书题材卡的「开场抓手 / 禁止漂移」？

**任一未勾 → 重写对应部分，不要带着缺陷进第 4 章。**

## 工具协同
- 用 `upsert_preference` 固化"开篇承诺"（主角欲望、核心冲突、首个甜头节点），让后续章节不漂移。
- 用 `update_chapter_plan` 把前三章的"钩子—甜头"节奏写进章节计划。
- 用 `create_reader_perspective_entry` 记录读者在前三章"已知 / 误知"态，验证钩子是否真造成了认知缺口。
- 前三章写完后，手动触发 `signability-audit` 做签约级开篇体检（本技能管"怎么写"，体检管"过不过签"）。
